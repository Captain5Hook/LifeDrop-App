# Deploying LifeDrop on Firebase Spark (Free Tier)

This guide covers deploying **LifeDrop** on Firebase Hosting and Cloud Firestore using the **Spark (free) plan** only—no Cloud Functions, no Cloud Storage, no paid APIs.

> **Important Configuration Values (from `firebase-applet-config.json`):**
> - **Firebase Project ID:** `aerial-channel-5bpf3`
> - **Named Firestore Database ID:** `ai-studio-7a64ef49-bd6d-49c3-8449-0f2403a6ee1a` *(LifeDrop uses a named Firestore database, NOT `(default)`)*

---

## 1. Prerequisites

1. **Node.js 20+** or **Bun** installed locally.
2. **Firebase CLI (`firebase-tools`):**
   ```bash
   npm install -g firebase-tools
   ```
3. Verify login:
   ```bash
   firebase login
   ```
4. Verify project selection matches `.firebaserc` (`aerial-channel-5bpf3`):
   ```bash
   firebase use
   ```

---

## 2. Install Dependencies, Verify, and Build

```bash
bun install
cp .env.example .env   # Optional VITE_* values can remain empty
bun run lint
bun run test
bun run test:rules
bun run eval:assistant
bun run build
```

Confirm the production build created:
- `dist/index.html`
- `dist/sw.js` (PWA Service Worker generated by `vite-plugin-pwa`)
- `dist/manifest.json`
- `dist/assets/` (hashed CSS/JS chunks including `vendor-react`, `vendor-firebase-core`, `vendor-firebase-auth`, `vendor-firebase-firestore`, `vendor-leaflet`)

---

## 3. Deploy Firestore Security Rules & Indexes

`firebase.json` is wired directly to the named database `ai-studio-7a64ef49-bd6d-49c3-8449-0f2403a6ee1a`:

```bash
npm run deploy:rules
# or:
firebase deploy --only firestore:rules,firestore:indexes
```

---

## 4. Deploy Static PWA Hosting

```bash
npm run deploy:hosting
# or:
firebase deploy --only hosting
```

After deployment finishes, the CLI prints your **Hosting URL**, typically:
- `https://aerial-channel-5bpf3.web.app`
- `https://aerial-channel-5bpf3.firebaseapp.com`

---

## 5. Authorize Domains in Firebase Authentication

Google Sign-In and Email verification links will fail if your live domain is missing from Firebase Auth allowlists:

1. Open the [Firebase Console](https://console.firebase.google.com/) and select project **`aerial-channel-5bpf3`** *(check the current Firebase console navigation if menu labels differ)*.
2. Go to **Authentication -> Settings -> Authorized domains**.
3. Ensure `aerial-channel-5bpf3.web.app` and `aerial-channel-5bpf3.firebaseapp.com` are listed (add any custom domain if used).
4. Under **Authentication -> Sign-in method**, ensure **Google** and **Email/Password** are enabled.

---

## 6. Grant Owner Admin Access (`/admins/<UID>`) in the Named Database

Admin access is checked dynamically via `exists(/databases/$(database)/documents/admins/$(request.auth.uid))` in `firestore.rules` (no email address is hardcoded).

1. Sign in to the deployed app once using your Google or verified Email/Password account.
2. Copy your **User UID** from **Firebase Console -> Authentication -> Users**.
3. Go to **Firebase Console -> Firestore Database**.
4. **CRITICAL:** Look at the database selector dropdown at the top of the Data panel *(check the current Firebase console UI position)* and switch it from `(default)` to **`ai-studio-7a64ef49-bd6d-49c3-8449-0f2403a6ee1a`**. Creating the document inside `(default)` will **not** work because `src/services/firebase.ts` and `firebase.json` bind to `ai-studio-7a64ef49-bd6d-49c3-8449-0f2403a6ee1a`.
5. Click **Start collection** -> Collection ID: `admins`.
6. Set **Document ID** to your exact Auth **UID** and add a field such as `role` (`string`) = `"admin"`.

---

## 7. Optional Security & App Check Hardening

1. **Restrict Browser Firebase API Key in Google Cloud Console:**
   - Open [Google Cloud Console](https://console.cloud.google.com/) -> **APIs & Services -> Credentials** *(check the current Cloud console labels)*.
   - Select your browser Firebase API key and set **Application restrictions** to **Websites (HTTP referrers)**.
   - Allow `https://aerial-channel-5bpf3.web.app/*`, `https://aerial-channel-5bpf3.firebaseapp.com/*`, and `http://localhost:3000/*` for local development.
2. **Optional Firebase App Check (Monitor Mode):**
   - Register your Hosting domains at **Google reCAPTCHA v3 Admin Console** to obtain a public **site key** (keep the secret key private on reCAPTCHA/Firebase only).
   - Register the reCAPTCHA v3 provider under **Firebase Console -> App Check** *(keep enforcement un-enforced / monitor mode initially until verified across mobile browsers)*.
   - Set `VITE_FIREBASE_APP_CHECK_SITE_KEY` in `.env` before rebuilding and redeploying Hosting.

---

## 8. Post-Deploy Verification & Lighthouse

1. **Run Mobile Lighthouse** against your deployed `.web.app` URL (or locally via `bun run preview -- --port 4173 --host 127.0.0.1`):
   ```bash
   npx lighthouse https://aerial-channel-5bpf3.web.app --preset=perf --only-categories=performance,accessibility,best-practices,seo --output=html --output-path=./docs/lighthouse.html
   ```
2. **Test Offline PWA on a Real Phone:**
   - Open `https://aerial-channel-5bpf3.web.app` in Android Chrome or iOS Safari.
   - Install to Home Screen ("Install app" banner or browser menu).
   - Switch the phone to **Airplane Mode**, reopen the installed app, open **Bleeding Emergency**, switch between **EN / हिन्दी / ಕನ್ನಡ**, and confirm `tel:108`, `tel:112`, and `tel:104` render cleanly.
3. **Run Live Firestore Emulator Suite (Requires JDK 17+):**
   ```bash
   npm run test:rules:emulator
   ```
